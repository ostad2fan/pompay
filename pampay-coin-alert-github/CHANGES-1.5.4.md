# PampDumpCoins — نسخه ۱.۵.۴ (versionCode 29)

۴ مورد از بازخورد کاربر روی v1.5.3 پیاده شد:

## ۱) صرافی البانک — رفع ریشه‌ای ارور 10203
- کد 10203 در مستند رسمی LBank یعنی «روش امضا با نوع کلید هماهنگ نیست» (签名方式错误).
- کلیدهای API جدید LBank به‌صورت پیش‌فرض **RSA** ساخته می‌شوند (Secret = کلید خصوصی PKCS#8). برنامه قبلاً همیشه `HmacSHA256` می‌فرستاد → سرور 10203 برمی‌گرداند.
- حالا نوع Secret خودکار تشخیص داده می‌شود:
  - Secret کوتاه (HMAC) → امضای HmacSHA256 مثل قبل.
  - Secret طولانی / PEM (RSA) → `signature_method=RSA` و امضای `Base64(SHA256withRSA(md5Upper))` — دقیقاً مثل مثال رسمی LBank.
- پیاده‌سازی RSA خالص TypeScript بدون کتابخانه جدید (`utils/rsaSign.ts`) — **۱۸/۱۸ تست در برابر openssl** (PKCS#8، PKCS#1، base64 خام، پیام فارسی).
- پیام‌های خطای LBank با کدهای رسمی دقیق شدند: 10205 (تحریم کشور/منطقة IP)، 10022 (مجوز/IP کلید)، 10600 (ساعت)، 10031 (echostr)، 10005/10006 (کلید)، 10004 (زیادی درخواست).

## ۲) باگ سوییچ «ربات تلگرام بک‌تست» — تاریخچه و معاملات پاک می‌شد
- **ریشه باگ**: با روشن کردن «اعلام تلگرام ۲۴/۷»، sync از سرور آرایه‌های خالی را روی داده‌های محلی می‌نوشت (سرور هنوز state نداشت) → همه پوزیشن‌ها و تاریخچه در برنامه ناپدید می‌شد و چرخة محلی هم دیگر اجرا نمی‌شد.
- **رفع (سمت برنامه)**:
  - sync همیشه **merge بر اساس id** است — هرگز داده محلی را با آرایه خالی سرور پاک نمی‌کند.
  - کانفیگ push حالا **snapshot وضعیت محلی** را هم می‌فرستد → سرور بک‌تست را از همان نقطه‌ای که برنامه بوده ادامه می‌دهد (تاریخچه حفظ می‌شود).
  - اگر sync به سرور شکست بخورد (سرور خاموش / deploy قدیمی)، چرخة **محلی** ادامه می‌دهد — ربات هرگز ساکت نمی‌شود.
- **رفع (سمت سرور)**:
  - اولین state خالی سرور با seed برنامه پر می‌شود (بدون له‌کردن state فعال خود سرور).
  - **توکن/چت‌آیدی تلگرام برنامه همراه کانفیگ به سرور می‌رود** — اعلان‌های ۲۴/۷ بدون راه‌اندازی جداگانه ربات تلگرام سرور کار می‌کنند (علت «حتی در تلگرام نمی‌آمد»).
  - پاسخ config/state حالا `telegramConfigured` دارد → برنامه اگر تلگرام وصل نباشد راهنما نشان می‌دهد.
  - announce سرور اول توکن اپ را امتحان می‌کند بعد تنظیمات خود سرور را.
- ⚠️ برای اعلان‌های ۲۴/۷ و seed، سرور Railway باید با کد جدید redeploy شود.

## ۳) دکمه ✂ (بستن بخشی از معامله) — درصد دلخواه + تایید
- با زدن ✂ دیگر مستقیم نصف بسته نمی‌شود؛ اول **پیغام/مودال** باز می‌شود:
  - حجم فعلی، مارجین و پیش‌نمایش «چند دلار از مارجین بسته می‌شود».
  - چیپ‌های ۲۵٪ / ۵۰٪ / ۷۵٪ + ورودی عدد دلخواه (۱۰ تا ۱۰۰ — ارقام فارسی هم پذیرفته می‌شود).
  - دکمه تایید «**ببند (X٪)**» — قرمز و درشت.
- ۱۰۰٪ (یا ≥۹۵٪) = بستن کامل معامله.
- حالت واقعی: سفارش reduceOnly — استاپ/تیکی صرافی روی حجم باقی‌مانده فعال می‌ماند.

## ۴) مارجین ورودی در پوزیشن‌ها
- روی هر پوزیشن باز (دمو و واقعی) ردیف جدید: «**مارجین ورودی: $X • ارزش پوزیشن: $Y**» (مارجین = حجم × قیمت ورود ÷ لوریج) — بعد از بستن بخشی از حجم، به‌صورت پویا کم می‌شود.
