# تغییرات نسخه ۱.۴.۵ (PamPay / PampDumpCoins)

نسخه ۱.۴.۵ یک نسخه **ترمیمی** است که چهار باگ گزارش‌شده کاربران را ریشه‌ای رفع می‌کند.
نصب روی نسخه ۱.۴.۴ بدون حذف برنامه انجام می‌شود (همان کلید امضای نسل ۴، versionCode 10).

---

## ۱) کرش «مدیریت دارایی» — ریشه‌ای رفع شد

**علامت:** بعد از افزودن یک صرافی (مثلاً ارزینجا با کلید اشتباه)، هر بار ورود به بخش
مدیریت دارایی، کل برنامه می‌پرید بیرون.

**علت واقعی (کد):** در `app/(tabs)/wallet/index.tsx` لیست کارت‌های صرافی از
`balanceQueries[idx]` رندر می‌شد، ولی آرایه `useQueries` فقط وقتی پر می‌شود که
snapshotهای کش AsyncStorage خوانده شده باشند (`cachesLoaded`). در فاصله چند صد
میلی‌ثانیه‌ای بین «لیست کیف پول‌ها لود شد» تا «کش‌ها آماده شد»، مقدار
`balanceQueries[idx]` برای کارت آخر `undefined` بود و `balanceQuery.data` روی آن
**TypeError** می‌داد → کرش کل اپ. اولین کیف پولِ ذخیره‌شده این باگ را فعال می‌کرد؛
چون اولین صرافیِ کاربر ارزینجا با کلید اشتباه بود، به‌اشتباه به کلید اشتباه نسبت
داده شد.

**رفع:**
- همه دسترسی‌ها به `balanceQuery` در `WalletItem` الان null-safe هستند
  (`balanceQuery?.data` و غیره) — کارت صرافی در آن فاصله به‌صورت «در حال دریافت»
  رندر می‌شود.
- `readBalanceCache` حالا **شکل داده را اعتبارسنجی** می‌کند (walletId/balances/
  totalValueUsd/lastUpdated) و سطرهای خراب را پاک‌سازی می‌کند؛ کش خراب حذف می‌شود،
  نه اینکه برنامه را بکشد.

## ۲) کلید API ارزینجا/نوبیتکس واقعاً استفاده می‌شود + بدون هنگ

**علت:** `fetchNobitexBalance` فقط کلیدهای سراسری پروژه را می‌فرستاد؛ کلیدی که
کاربر در فرم «افزودن صرافی» وارد می‌کرد **کاملاً نادیده گرفته می‌شد** — یعنی حتی با
کلید درست هم موجودی شخصی نمی‌آمد.

**رفع:**
- واریانت‌های احراز هویت حالا **اول کلید خودِ کیف پول** (همان که کاربر وارد کرده)
  را امتحان می‌کنند، بعد کلیدهای سراسری، بعد anonymous.
- هر درخواست ۱۲ ثانیه timeout دارد — دیگر فرمی چند دقیقه هنگ نمی‌کند.

## ۳) ورود بیت‌پرپ — «[object Object]» برای همیشه رفع شد

**علت دو‌قسمتی:**
1. اپ فیلد کد تأیید را با نام `code` می‌فرستاد، ولی API واقعی بیت‌پرپ (FastAPI V3)
   طبق وب‌اپ رسمی خود صرافی **`otp` + `device_id`** انتظار دارد → سرور همیشه 422
   (خطای اعتبارسنجی) برمی‌گرداند.
2. بدنه خطای FastAPI شکل `{"detail": [{...}]}` دارد؛ کد قبلی `String(detail)` می‌زد
   → روی صفحه «[object Object]» چاپ می‌شد.

**رفع:**
- `bitperpVerifyOtp` حالا `{ email, otp, device_id }` می‌فرستد (ایمیل lowercase،
  device_id پایدار و ذخیره‌شده در AsyncStorage — همان رفتار وب‌اپ رسمی).
- `extractApiErrorMessage` جدید هر شکلی از خطا (string / آبجکت / آرایه اعتبارسنجی
  FastAPI) را به پیام فارسی خوانا تبدیل می‌کند.
- همه درخواست‌های بیت‌پرپ ۲۵ ثانیه timeout دارند.

## ۴) دکمه‌های تنظیمات: سریع + دلیل دقیق خطا

**علت:** fetchهای تنظیمات (همگام‌سازی پیکربندی، ثبت پوش، تست تلگرام) **بدون
timeout** بودند؛ وقتی سرور خاموش است، هر درخواست دقایق معلق می‌ماند («دکمه با تأخیر
اجرا می‌شود»). تست سرور هم ۳ مسیر × ۱۲ ثانیه = تا ۳۶ ثانیه طول می‌کشید.

**رفع:**
- timeoutهای ۸–۱۲ ثانیه روی همه مسیرهای سرور (`syncScanConfig`،
  `fetchServerSignals`، `/bot/pending`، `/bot/ack`، `/push/register`، `/bot/test`).
- `testServerUrl` الان بین این‌ها **تفکیک قائل می‌شود**:
  - **502/503/504 → «سرور خاموش/کرش است — در پنل Railway دوباره دیپلوی کنید»**
  - **404 → «چنین سروری پیدا نشد — آدرس را چک کنید»**
  - timeout شبکه → «اینترنت/فیلترشکن را چک کنید»
- تست سرور به ۶ ثانیه per-path کاهش یافت (حداکثر ۱۸ ثانیه).

## ۵) سخت‌افزار کردن سرور (Railway)

**وضعیت کشف‌شده:** سرویس Railway کاربر موقع تست زنده **HTTP 502** می‌داد — سرویس
کرش کرده/متوقف است. سیاست ری‌استارت Railway (۵ تلاش) هم قبلاً مصرف شده بوده.

**رفع در کد سرور (`server/src/index.ts`):**
- `process.on('uncaughtException' / 'unhandledRejection')` → خطا **log** می‌شود،
  سرویس زنده می‌ماند (قبلاً هر خطای مدیریت‌نشده کل سرویس را می‌کشت و بعد از ۵ بار
  Railway کلاً ول می‌کرد کرد → 502 همیشگی).
- راه‌اندازی poller دستورات بات داخل try/catch.
- لاگ حافظه هر ۶۰ ثانیه برای تشخیص OOM.

**اقدام لازم کاربر (یک بار):** در پنل Railway → پروژه PomPay → سرویس backend →
**Redeploy** (یا Restart). تا این کار انجام نشود، اعلان‌های ۲۴ساعته و دستورات
تلگرام با برنامه‌بسته کار نخواهند کرد (خود اپ سالم است — فقط مسیر سرور خاموش است).

وقتی فایل جدید روی گیت‌هاب گذاشتید و نسخه هنوز قدیمی نشان داده می‌شود، فقط این
دو لینک را **در مرورگر باز کنید** (هر کدام تا ~۱۰ دقیقه طول می‌کشد، صفحه سبز
Purge successful می‌آید):

