# تغییرات نسخه ۱.۴.۶ — دارایی برای همه صرافی‌ها + تشخیص دقیق خطا

این نسخه روی همان کد پایدار ۱.۴.۵ (بدون بازطراحی UI) ساخته شده و دو مشکل گزارش‌شده را ریشه‌ای رفع می‌کند:

## ۱) مدیریت دارایی: همه صرافی‌های لیست فعال شدند

**مشکل:** فقط Binance / Bybit / OKX / ارزینجا / نوبیتکس / بیت‌پرپ موجودی نشان می‌دادند. افزودن هر صرافی دیگر (مثلاً هوبی، مکسی، OKX) خطای «صرافی پشتیبانی نمی‌شود» یا موجودی خالی می‌داد.

**رفع:** فایل جدید `utils/foreignExchangeBalances.ts` برای تک‌تک صرافی‌های لیست، دریافت موجودی واقعی از API خود صرافی را پیاده‌سازی می‌کند:

| صرافی | روش احراز هویت | وضعیت اعتبارسنجی امضا |
|---|---|---|
| MEXC | امضای Binance-style + هدر `X-MEXC-APIKEY` | ✅ تست واقعی (خطای کلید = فرمت درست) |
| KuCoin | هدرهای `KC-API-*` نسخه ۲ + Passphrase امضاشده | ✅ تست واقعی |
| Bitget | هدرهای `ACCESS-*` + Passphrase | ✅ تست واقعی |
| Gate.io | HMAC-SHA512 (روش رسمی v4) | ✅ تست واقعی |
| Huobi / HTX | دو مرحله‌ای رسمی HTX (HmacSHA256 Base64) | ✅ تست واقعی |
| Toobit | هدر `X-BB-APIKEY` + مسیر رسمی `/api/v1/account` | ✅ مستند رسمی |
| BingX | هدر `X-BX-APIKEY` + امضای Binance-style | ✅ تست واقعی |
| BitMart | هدرهای `X-BM-*` | 🔄 دو واریانت امضا (خطای sign → واریانت دوم) |
| SuperEx | Binance-compatible + ۳ مسیر کاندید | 🞍 مقاوم با تلاش چند مسیر |
| CoinEx | هدرهای `X-COINEX-*` (v2) | 🔄 دو واریانت امضا |
| Phemex | هدرهای `x-phemex-*` | 🔄 دو واریانت امضا |
| LBank | POST فرم + امضای MD5 (روش v2) | 🔄 یک روش |
| XT | مسیر fapi.xt.com | 🔄 دو واریانت امضا |
| Bitunix | هدرهای `apikey/timestamp/sign` | 🔄 دو واریانت امضا |
| KCEX | Binance-compatible | 🞍 ۳ مسیر کاندید |
| ایرانیکارت | پلتفرم سازگار با نوبیتکس (Token auth) | 🞍 تلاش با کلید خود کاربر |
| Orbiter | — | ⚠️ پل L2 است نه صرافی؛ پیام دقیق فارسی می‌دهد |

صنعتی‌ترین بخش این پیاده‌سازی **اعتبارسنجی تجربی امضاها** بود: برای هر صرافی درخواست امضاشده با کلید ساختگی فرستاده شد؛ اگر پاسخ خطای «کلید نامعتبر» بود یعنی فرمت امضا پذیرفته شده (روش درست)، اگر «امضای نامعتبر» بود فرمت اشتباه بود و اصلاح شد. صرافی‌هایی که از سرور تست قابل دسترسی نبودند (فایروال/جئو) دو واریانت امضای مستند را به‌ترتیب امتحان می‌کنند.

## ۲) دلیل دقیق هر خطا به فارسی (قبلا: موجودی خالی بی‌توضیح)

- **OKX و Bybit** موقع خطای کلید، HTTP 200 با کد خطا داخل بدنه برمی‌گردانند — کد قبلی این را نادیده می‌گرفت و کارت را «بدون دارایی» نشان می‌داد. حالا کد و پیام دقیق OKX/Bybit به فارسی نمایش داده می‌شود (مثلاً: کلید یا Passphrase اشتباه است + توضیح اینکه Passphrase چیست).
- **Binance** در صورت کلید نامعتبر حالا خطای دقیق (کد ‎-2014/-2015) با راهنمای «Enable Reading» نشان می‌دهد.
- **همه صرافی‌های جدید** خطای API خود صرافی را عیناً فارسی‌سازی شده نشان می‌دهند (کلید اشتباه / دسترسی خواندن خاموش / passphrase غلط / خطای شبکه با راهنمای فیلترشکن).
- **Passphrase**: فرم افزودن صرافی حالا برای KuCoin و Bitget هم فیلد Passphrase نشان می‌دهد (مثل OKX) — بدون آن امضای این دو صرافی هرگز قبول نمی‌شود.

## ۳) تست اتصال سرور — تشخیص طرفِ خراب

**مشکل:** وقتی سرور Railway معلق/خاموش است (اتصال TLS برقرار ولی هیچ پاسخی نمی‌آید)، تست اتصال به‌اشتباه می‌گفت «اینترنت یا فیلترشکن خودتان را چک کنید».

**رفع:** اگر هر ۳ مسیر تست (`/ping` و `/health` و `/scan/status`) در سطح شبکه شکست بخورند، برنامه ۳ سرویس مرجع (بایننس / گوگل / گیت‌هاب) را موازی می‌سنجد:

- هر کدام جواب داد → اینترنت شما سالم است → پیام: «سرور Railway خاموش یا معلق شده؛ از پنل Railway دوباره Redeploy/Restart کنید»
- هیچ‌کدام جواب نداد → پیام: «اینترنت یا فیلترشکن گوشی قطع است — روشن کنید و دوباره تست بزنید»

«تست ارسال تلگرام از سرور» هم همین تشخیص را دارد.

## ۴) وضعیت سرور Railway در زمان انتشار

سرور `pompay-production.up.railway.app` در زمان ساخت این نسخه **معلق** است (اتصال TLS برقرار می‌شود ولی هیچ پاسخی نمی‌آید — حتی از خارج ایران تست شد). کد سرور مشکل ندارد؛ سرویس باید یک بار از پنل Railway **Redeploy** شود. بعد از Redeploy، اعلان‌های ۲۴ ساعته و دستورات تلگرام دوباره فعال می‌شوند.
